# 合成运动标注模块：已定方向与待办

此页是 `imu-motion-simulator/docs/productization-roadmap.md` 在标注平台侧的实施入口。截至 2026-09-17，本仓库已实现合成运动页面/API 的本地 pilot，但**未部署到生产，也未正式接受任何合成候选**。现有真实设备录制、同步、`review.json` 与 HDF5 3.2 路径保持独立。

## 模块边界

- 在现有 annotation 应用中增加单独的合成运动导航、`/api/v1/synthetic/` API 和专用存储服务；复用现有身份验证、对象存储抽象及部署外壳，不直接导入模拟器 Python 包。
- 从 `soft3888-label` bucket 的 `synthetic-motion/dev/<run-id>/v1/` 读取逐 clip **提交记录**。发布器在写提交记录前上传并核验对象；队列按提交记录发现候选，打开详情及读取预览时再次检查对象大小、声明的哈希元数据或实际内容哈希。静态 Three.js 资源共享缓存，播放与 IMU 曲线对应同一 motion/selection/layout。
- 审核页先判断动作和 IMU 是否可用。页面沿用标注工作台的固定视口和任务抽屉，整页不滚动；质量 pass 可以没有正式标签，reject 必须有结构化原因或自定义说明。动作预览下方显示同步的可放大 IMU 幅值曲线，支持选择传感器、点击定位和拖动缩放。短租约队列避免多人同时审核同一条，支持跳过、续租、状态筛选与快捷键；展开正式标签列表时空格仍控制播放。已通过和已拒绝可由任一审核员独占领取复审，改为另一决定或撤回到未审核；标签待办中发现质量问题也可直接退回。退回条目在未审核队列置顶供其他审核员领取，正式标签和旧快照保留，同一审核员暂不自动领回。每次决定保存不可变 revision，绑定 candidate 版本和输入哈希；并发冲突要求刷新后重试。机器 QA 仅提示，不代替人工接受。
- 正式活动标签是独立流程。统一的“概念库”入口管理真实 IMU 共用概念和动捕专用概念，后者不会出现在真实 IMU 标注选择器；来源标签只在正式选择器上方作为参考，不进入受控选项。管理员可维护动捕专用概念，也可从已观测来源值列表选择或手动输入精确来源词来创建映射草稿；创建前显示命中数，草稿仍须回放抽检后才可启用。映射歧义或缺失时仍需人工选标签，跌倒不得自动映射。标签 revision 与映射解析都按版本冻结。
- “创建合成训练快照”位于训练快照页的合成 HDF5 3.3 标签页，与真实 HDF5 3.2 分开。点击时只冻结完整发布、最新质量 revision 为 pass 且有正式标签的候选；至少一条满足条件才可提交。平台写不可变请求，Ubuntu 上的独立 SDK 工作进程构建和验证 replay-only HDF5 3.3，平台显示状态与分片下载。reject/未审核/未贴标签只在审计中；撤回保留正式标签，但在再次通过前不进入新快照，已冻结的旧快照不变。
- 该模块的候选、审核 revision、快照请求、对象前缀与真实设备录制完全分开。标注平台不负责动捕解码、IMU 生产或重型 HDF5 构建。

- [x] **基础合同薄切片**：本地对象存储测试已覆盖未提交不可见、不可变 revision、并发冲突和快照冻结；一条仅用于基础设施测试的 pass 已驱动真实 HDF5 3.3 分片验证。它不是用户人工接受，未写到 GCS。
- [x] **本地工作台增量**：质量/标签拆分、统一概念库与草稿映射、来源词观测列表、短租约队列、分页、快捷键、结构化拒绝、固定视口任务抽屉、同步可放大曲线、双向复审/退回置顶、上传进度汇总和快照状态/下载已实现；本地浏览器加载了 12 条现有 GCS 试点。试用服务只从 GCS 读候选，测试审核决定只写本机 `/tmp`，未写云端审核决定。
- [ ] **端到端验收**：用户检查真实界面手感；补足 GCS 断网/缺失对象/哈希失败、并发改判与 worker 失败恢复测试；至少由真实人工 pass 构建并验证一个 GCS 小快照。单实例自动轮询快照 worker 与本地 4 GiB 内合并/资产去重已实现，多实例协调、真实大快照压力测试及大规模标签待办筛选仍待实现。
- [ ] **正式上线**：只清理合成运动测试命名空间的在线可见对象和测试决定，不改变共享 bucket soft-delete 策略，也不触碰其他团队数据；随后从权威本地来源重新生产、正式全量及增量上传、部署生产模块，并从空审核状态重新开始。

Python SDK/CLI 属于模拟器生产内核；未来可选 Web **生产控制面板**负责运行任务和观察吞吐，与本人工标注模块不是同一页面，也不是 SDK 使用的前提。原始动捕/模型的私有 GCS 归档、Google CPU VM/Cloud Batch、BVH 生产验证和开源发布均为后续阶段，不能视为此模块已具备的能力。
