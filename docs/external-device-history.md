# 外部设备历史数据

云端标注平台可通过 Synerglobal 的只读 API 同步手表和床垫历史。
功能默认关闭。开启后，后台发现所有可见设备，新设备自动加入；设备从上游列表消失时，
已保存的记录继续可读。所有已认证的平台成员可浏览和下载，同步管理始终需要管理员权限。

## 页面与时间

页面入口为 `?view=external`。左侧按手表、床垫列出设备，右侧显示指标选择器和一张大图。
导航入口位于“数据管理”之后。各类型内，全部已归档记录数为零的设备默认折叠在“暂无数据”中，
不受当前时间范围和指标影响；直接打开空设备链接时自动展开，新数据到达后自动回到普通设备列表。
桌面使用固定视口工作台，页面主体不滚动；设备列表和详情侧栏内部滚动。
窄屏将设备列表收进抽屉。原始记录、覆盖说明、同步管理在“详情”中按需读取。

默认显示截至当前的近一周。预设“近1日／周／月／年”分别为过去 24 小时／7 天／30 天／365 天，
另有全部、自定义起止时间、图内拖选放大和返回上个范围。
设备、指标及时间选择保存在 URL 的 `device`、`metric`、`range` 参数；自定义范围使用 `from`、`to`。
常用指标直接显示为按钮：床垫为心率、呼吸率、在床和睡眠状态；手表为心率、血氧、总步数和累计热量。
仅显示实际收到数据的指标，其余放在“更多指标”。每种设备类型分别记住手动选择，显式 URL 指标优先。
切换设备保留时间范围。顶部始终展示当前指标最近上报时间，可跳到以最新记录加 1 毫秒为终点的 24 小时，
并通过“返回上个范围”恢复之前范围。设备列表直接显示最近上报时间；完成的任务详情收在侧栏。

图表复用 uPlot，按时间范围和画布宽度自动选择聚合粒度。连续数值显示均值及最小/最大值阴影，
状态使用众数阶梯线（并列取最近状态），悬停展示状态样本占比，不将其解释为持续时间。
总步数 ST、运动时长 STTIME、累计距离 distance_km、累计热量 energy_kcal 显示桶末值，
区间步数 CST 显示桶内合计。distance_km = LK.DTC / 100，energy_kcal = LK.KCAL / 10；
原始 KCAL 仍保留原指标键和均值聚合。CO 充电状态采用阶梯线（0 未充电、1 充电中、2 完成），
其他代码原样标记为未知。床垫 REALTIME.Amp_value 显示均值及范围，单位保留“原值”。空桶不补零，合成与未标记合成数据分别统计。
“连接数据点”默认开启，选择保存在当前浏览器中：跨空桶连接同一来源的有效点，最小/最大值阴影仍在空桶处断开。
关闭后只显示散点，悬停仍可查看统计范围；两种模式都保留可见数据点。连线仅辅助阅读，不插值或新增记录。
点击聚合点打开该时间桶的原始记录列表，聚合结果本身不会当作原始记录展示或下载。

查询统一使用服务器接收时间 `receivedAt`，区间为 `[start,end)`。
数据库保留 UTC，时间显示与输入按北京时间解释。原始设备时间不替换接收时间。
“同步成功”与“有新数据”分开显示；历史未补齐、部分覆盖、合成记录保留简短标记，详情中可查看缺口。

## 睡眠报告、报警与字段

床垫的“睡眠报告”侧栏按接收时间从新到旧显示全部归档报告。有效标志非 1、缺失或核心字段不完整的
报告默认放入可展开分组；缺失值不会补零。摘要突出睡眠时间、时长、心率/呼吸率与原始评分，
设备身份、其他报告字段、数组及原始 JSON 按需展开。报告字段的单位、时区及状态码尚未确认，
页面明确保留原值，不推断诊断、时间单位或各睡眠阶段持续时间。

手表 UALM 与床垫 WARNING 显示在同一图表顶部，按图表时间粒度聚合且区分合成标记。
点击标记查看该桶内可分页的报警上报及完整原始记录；“详情 → 报警”查看当前范围的所有报警。
DROP 仅显示为上游原始代码，不将合成样例解释为真实跌倒。
“详情 → 字段”列出当前采用记录中的字段路径、消息类型、出现次数、单位和解析状态。
HRV、C、RDS_ID、Pressure_On/Off 等未确认语义的字段继续保留原值。

## 保存与恢复

- 现有 GCS / 本地 ObjectStore 的 `external-device-data/synerglobal/archives/` 保存完整
  HTTP JSON 响应的 gzip 文件及不可变清单。清单记录设备、时间范围、拉取时间和双重 SHA-256。
- `external-devices.sqlite3` 与标注 catalog 同目录，使用独立 WAL 数据库保存设备目录、
  记录索引、关键数值、归档引用、内容版本、连续覆盖区间和任务。浏览不会调用外部 API。
- 分钟、小时、天的聚合统计保存在同一数据库，随原始索引事务更新。版本修订或接收时间变化会
  重算受影响的桶；长范围查询读取聚合索引，边界采用更细粒度裁剪。旧数据库在 worker 启动时
  补建统计，原始归档保持不变；重建后可以恢复全部聚合统计。
- `control.json` 保存设备发现边界与管理员确认的历史起点，供索引恢复使用。
- 手表在设备内按记录 ID 去重；床垫按完整产品／设备身份、消息类型和记录 ID 去重。
  普通更新遇到已有标识不修改原记录，全量重建使用本次接口内容；旧版本原始归档均保留。
- 原始记录持续保留，不进入 IMU 六轴训练或标注工作流。现有训练快照垃圾回收不管理该前缀。

原始对象先写、不可变清单最后写，索引事务成功后才完成任务。上传或索引失败不会推进覆盖。
启动 worker 时重放尚未索引的清单，恢复中断任务；原文与下载读取均校验归档 SHA-256。
数据库丢失后可从对象存储重建，生成过的下载任务历史属于派生状态，可重新导出。

## 更新数据与全量重建

主界面的“更新数据”统一刷新两类设备目录及数据，不需要先单独刷新列表。默认每 15 分钟自动执行一次。
管理员可在“详情 → 管理”设置统一历史起点，默认北京时间 **2026-09-01 00:00**；这是用户设定的查询范围，
并不表示接口方已确认更早没有历史。修改起点用于新设备和下一次重建，不删除现有记录。

新设备从统一起点首次补齐；已有不完整归档按实际覆盖区间补缺。完成初始化的设备从连续成功查询的终点
更新至任务创建时的截止时间，不使用最后一条记录时间，不回看最近 30 分钟。空响应推进覆盖，失败区间不能跳过。
普通更新只新增未见过的记录身份，不覆盖既有记录。上游对早期历史的修改、补写和删除由全量重建核对。
旧设备增量优先于新设备首次补齐；首次同步尚未完成的设备保持可见，完成后仍为零记录的设备才进入折叠组。

查询初始窗口最长一天，超过 16 MiB 或 75 秒预算时二分，最小窗口不超过一分钟。
单 worker 串行请求，跨进程文件锁避免重复工作；网页关闭不影响执行。同类进行中任务重复提交返回同一任务 ID，
更新与重建不能同时运行。失败可手动重试，普通自动更新下一周期补缺；凭据被拒绝时暂停，修复后重试。
状态返回设备/区间进度、请求数、响应体积、入库数量、实际耗时及失败原因。没有真实 worker 心跳和凭据配置时，
页面显示“未连接同步服务”，不会用预览心跳模拟同步正常。

“全量重建”要求二次确认起点及替换行为：重新获取当前目录，从统一起点到本次截止时间完整拉取，
在独立数据版本中构建数据库和聚合索引。期间旧库供浏览下载，普通更新暂停；全部成功、覆盖完整且 SQLite
完整性检查通过后才切换。失败保留旧库；成功后补齐重建耗时期间的增量。接口不提供跨请求的事务快照。

`external-device-control.sqlite3` 独立保存任务、设置及活跃版本。原库保留为 `legacy`，新库位于
`external-device-generations/<版本>.sqlite3`，对应对象位于 `external-device-data/synerglobal/generations/<版本>/`。
`runtime.json` 保存可恢复的活跃指针；切换不替换正在读取的 SQLite/WAL 文件，每个请求和导出固定绑定一个版本。
旧库及原始归档不自动删除；恢复仅重放各自版本的归档，并按归档顺序保持增量“只新增”的行为。
`external-rebuild-index` 仅从已有归档恢复索引并补齐新增投影，与调用上游的“全量重建”不同。
新增字段/报告/事件索引由 worker 在同步循环间分批补齐，不调用上游。每批按当前 `records` 的
archive_id、position、hash 校验原文，不重放历史旧版本覆盖当前记录；检查点与字段计数在同一事务提交。
中断后可恢复。每台设备完成新增分钟/小时/天统计后才公开新增指标、报告和事件；原有指标继续可用。
`GET metrics` 的 `preparation` 给出该设备新增投影的阶段、就绪标志与已扫描记录数。
字段清单通过复用相同字段签名计数，避免为每条高频记录重复保存完整字段目录。
旧 `POST history` 保留接口方确认语义；日常起点设置通过 `PUT settings`，不会伪造接口方确认。

## 下载

设备行的下载按钮生成该设备全部已归档原始记录的 ZIP，包含
`records.json`、`records.csv`、`manifest.json`，与图表时间范围和指标无关。
手表／床垫分组上的按钮下载该类型全部已保存设备，包括从上游消失的已归档设备。
类型 ZIP 用平台设备 ID 分目录，目录内保留上述三个文件，顶层清单记录设备列表；
同编号、不同产品的设备不会混合。任务创建时固定设备集合，生成时所有设备共用同一数据快照。
按钮显示准备状态，完成后自动触发下载并提供再次下载链接；失败时在原处重试。
JSON 保留每条记录的字段、类型、payload 和 rawPayload；CSV 提供关键数值、完整 payload JSON
及原文。已有 CSV 列及其顺序不变；Amp_value、CO、distance_km、STTIME、energy_kcal
追加在末尾，清单的 `csv_additions` 说明单位，原始 KCAL 列保持原值。CSV 会转义可能被电子表格当作公式的字符串，JSON 保留源字符串。
清单注明来源、时间范围、覆盖缺口、合成记录数、文件 SHA-256 和字节数。
部分覆盖也可下载，清单不会把它标为完整历史。下载接口支持单段 HTTP Range。

导出在独立线程中读取 SQLite 一致性快照，不阻塞 worker 的上游同步请求。
派生 ZIP 位于同一前缀的 `exports/`；普通成员不能通过猜测 URL 绕过平台权限。

## 配置和运行

在服务端配置加入 `configs/server.annotation.example.yaml` 中的 `external_devices` 段。
设置 `enabled: true` 后，所有已认证平台成员可见页面，访问范围默认为 `access: members`。
可显式配置 `access: admins` 限制为管理员浏览；两种设置下管理接口均仅管理员可用。

worker 仅从 `IMU_SYNERGLOBAL_API_KEY` 环境变量读取密钥，访问域名固定为
`https://api.synerglobal.com.au`，使用正常 TLS 验证，不跟随重定向。
不要把密钥放进仓库 YAML、前端配置、命令行参数或下载文件。

生产服务单元为 `configs/systemd/imu-external-devices.service`。
其私有 EnvironmentFile 是 `/etc/imu-annotation/external-devices.env`，只包含：

```dotenv
IMU_SYNERGLOBAL_API_KEY=<由部署环境安全注入>
```

该文件需限制为服务账号／管理员可读。worker 与标注 API 使用同一服务器配置和
`/var/lib/imu-annotation` 数据目录，但 API 服务无需读取密钥。

```sh
imu-annotation --config /etc/imu-annotation/config.yaml external-sync
imu-annotation --config /etc/imu-annotation/config.yaml external-sync-once
imu-annotation --config /etc/imu-annotation/config.yaml external-rebuild-index
```

`external-sync-once` 执行一次调度循环和最多一个同步窗口，适合检查配置，不代表完成整个补拉。
`GET status` 包含当前数据版本、worker 可用性及最新/进行中任务的阶段、进度和实际耗时。
运行 `external-rebuild-index` 前先停止 worker；该命令持有同一文件锁。网页“全量重建”则由运行中的 worker 执行，无需停服务。

发布时先部署代码与前端构建，再配置功能和 worker。确认成员能看到设备与曲线并下载、
增量时间窗成功归档、普通成员无法修改同步设置或执行更新与重建后，保持 worker 运行。
部署包包含 worker 服务；后续发布和回滚会停止旧 worker，并按目标版本与配置启动。
首次启用前备份私有配置；回滚到不含该模块的旧版本时，先停用 worker 并恢复未包含
`external_devices` 段的配置，保留全部归档和数据库。

## 后端接口

全部位于 `/api/v1/external-devices/`，复用平台认证：

| 接口 | 行为 |
| --- | --- |
| `GET status` / `GET devices` | worker 状态与设备目录 |
| `GET devices/{id}/calendar?year=&month=` | 北京时间日历及覆盖状态 |
| `GET devices/{id}/records?start=&end=&cursor=&message=` | 游标分页记录、数量和覆盖信息 |
| `GET devices/{id}/records/{record_id}` | 原始记录文本、rawPayload、版本摘要 |
| `GET devices/{id}/metrics` | 已有历史的可用指标、单位、最早/最新时间及统计就绪状态 |
| `GET devices/{id}/series?start=&end=&metric=&point_budget=` | 单指标聚合，返回粒度、统计值、样本数、合成标记及覆盖信息 |
| `GET devices/{id}/fields` | 字段出现次数、已解析/原值/缺失状态与单位说明 |
| `GET devices/{id}/reports?valid=&start=&end=&cursor=&limit=` | 可选有效性及范围筛选，按接收时间倒序分页，默认全部历史 |
| `GET devices/{id}/reports/{record_id}` | 睡眠报告原值摘要及完整字段/序列 |
| `GET devices/{id}/events?start=&end=&point_budget=` | 报警时间桶、数量和合成标记，半开区间 |
| `GET devices/{id}/events/records?start=&end=&cursor=&limit=` | 报警详情倒序分页，原文使用原有记录接口 |
| `POST sync` | 管理员发起更新任务；返回任务 ID、状态与计数；进行中合并 |
| `POST rebuild` | `{confirmed:true,history_start}`；确认起点仍匹配后排队全量重建 |
| `PUT settings` | `{history_start}`；保存用户设定的统一起点，进行中禁止修改 |
| `POST history` | 管理员提交 `start` 与 `confirmed_by_provider: true` |
| `POST exports` | `{scope:"device",device_id}` 或 `{scope:"kind",kind:"mattress"/"radar-watch"}` 创建全量任务 |
| `GET exports/{id}` / `GET exports/{id}/download` | 单任务状态和受权下载 |

浏览器中的设备 ID 为平台生成的标识，后端负责映射为完整 `historyDeviceNo`。
`point_budget` 为每条来源曲线的目标桶数，范围 100–2000，空桶也计入。
旧日历接口、不带 `metric` 的曲线接口，以及提交 `device_id/start/end` 的时间范围导出保持兼容。
