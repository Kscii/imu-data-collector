# v0.3.0 — Linux source and cloud platform

## Availability

This release publishes Linux source code and installation instructions and updates the cloud
annotation service and upload broker. Use the source archives attached automatically to the
`v0.3.0` GitHub release. No new Windows EXE, macOS DMG or Linux binary installer is published.

**Windows/macOS releases are deferred because the client's replacement-device parameters
are not ready. The coefficients in the supplied documentation do not match the current
sensor. We are awaiting corrected documentation or a device matching that documentation.**

**客户设备参数尚未到位：现有文档中的系数与当前新设备不匹配，需等待正确文档或匹配设备，
因此本轮暂不发布 Windows/macOS 新版本。Linux 新设备同样仅限 test 原始数据采集。**

## Changes since desktop-v0.2.0

- Multi-IMU selection by project SN/revision, with separate CW12EU-T and ABF0 protocol adapters.
  The replacement device preserves raw notifications, six-axis counts and its local clock.
- Versioned device configuration Snapshot v2, local workspaces and last-known-good caches,
  team submission/review APIs, and explicit separation of candidate SI from verified calibration.
- Configuration and SI provenance frozen in capture HDF5 1.9 and manifest 3.2. Existing
  training and client-delivery HDF5 3.2 contracts remain in use; historical files stay immutable.
- A clearer capture/settings workbench, configuration form guards, bounded recording queues,
  and restored catalog identity-repair states.
- Improved English/Chinese UI and actionable login/error messages, plus bilingual
  documentation of the full recording-to-delivery data pipeline.
- Frontend behavior/language tests included in CI alongside backend validation and both builds.

## Installation and verification

Follow [Linux source installation](../linux-source-install.md). Use Python 3.12, Node.js 24
and the committed dependency locks. The source application starts a local browser UI;
private maintainer systemd/GCS configuration is not required.

Release evidence records local automated checks, isolated Linux startup, available hardware
observations, and the exact deployed commit. A successful software or protocol check is not
verification of replacement-device SI coefficients, clinical accuracy or untested platforms.
Before publication, local validation passed 282 backend tests, 7 frontend test files, both
frontend builds and Ruff. An isolated Chromium session rendered the English and Chinese
settings pages without JavaScript errors and confirmed matching frontend/backend build IDs.
The replacement-device prod request was rejected with HTTP 422. Both data-pipeline Mermaid
diagrams rendered and the changed documentation's relative links resolved.

The replacement sensor was not found during this release's 10-second BLE scan, so a new
physical recording could not be completed at that checkpoint. The earlier
[2026-09-08 device audit](../device-audits/IMU-0002-R01-2026-09-08.md) remains historical
protocol evidence, not a new recording or calibration result. Final release evidence records
any later device availability separately.

See the [release checklist](../release-v0.3.0-checklist.md); final deployment evidence is
attached to the GitHub release after the matching cloud deployment is verified.

## Data and device limits

`IMU-0002-R01` remains `commissioning` and test-only. Official SI output is unavailable
(`values_si` remains NaN); local candidate conversion is only diagnostic. This release does
not approve/revoke any device Snapshot, change team Current, migrate existing recordings,
or publish a new training dataset. The original reported-faulty CW12EU-T unit is not treated
as usable hardware merely because its validated historical profile remains available.

Linux-source `v*` releases and the existing `desktop-v*` packaging workflow are distinct.
Previous desktop releases retain their historical platform/verification status.
