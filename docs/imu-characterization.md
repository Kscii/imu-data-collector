# CW12EU-T IMU 表征与校准候选

## 目的和结论边界

表征的目标是回答“当前 16-byte 候选帧是否真的是六轴 IMU、顺序和符号是什么、比例是多少、
长时是否稳定”，而不是先假定供应商口头参数正确。所有实验先保存原始 BLE 通知和
`int16` 计数，自动报告只给出候选结论：

- 表征 H5 固定 `recording_kind=imu_characterization`。
- 视频不是该实验的必需输入，`video_status=not_requested`。
- H5 与报告均固定 `training_eligible=false`。
- 在三个加速度轴比例、三个陀螺仪轴比例与符号被独立验证前，训练 SI 数组继续保持 `NaN`。

设备坐标系约定：+X 指向佩戴者右侧，+Y 指向头部/挂绳端，+Z 指向身体外侧/按键面。
这是平台使用的目标坐标系，不代表目前已经证明候选原始列与它一一对应。

## 推荐实验顺序

在本地 WebUI 的“IMU 表征”页开始一个会话，再依次开始/结束阶段：

1. `pipeline_smoke_uncontrolled`：10 秒即可，只验证连接、H5 和报告链路，不参与校准。
2. `long_static_button_up`：按键面朝上静置至少 30 分钟，用于样本率、包间隙、噪声和零偏。
3. `button_face_up` 与 `button_face_down`：各 60 秒，形成稳定的 ±Z 候选对。
4. `interface_face_up` 与 `interface_opposite_face_up`：各 60 秒，形成稳定的 ±X 候选对。
5. 两个 `pendant_*_exploratory`：外壳在挂绳方向无法稳定放置，目前只能手持探索；不能据此正式冻结 Y 比例。
6. `gyro_{x,y,z}_{positive,negative}`：正反旋转用于识别响应轴和符号。没有转台或已知角速度时，不能验证 `counts/(°/s)`。

每次改变姿态后先等待设备稳定，再开始阶段。夹具、支撑面、手持抖动或意外移动写入阶段备注。
如果以后能制作不会压迫按键/接口的夹具，应重新采集 ±Y，而不是升级当前探索结论。

## 命令行冒烟与长静态

姿态未受控的 10 秒链路冒烟：

```bash
uv run imu-collector characterize-imu \
  --operator xfan0282 \
  --stage pipeline_smoke_uncontrolled \
  --seconds 10 \
  --notes "姿态未控制，只验证链路"
```

设备已确认按键面朝上并稳定放置后，执行 30 分钟长静态：

```bash
uv run imu-collector characterize-imu \
  --operator xfan0282 \
  --stage long_static_button_up \
  --seconds 1800 \
  --notes "按键面朝上，桌面静置"
```

停止时会先重建候选样本时间，再完成 H5、计算 SHA-256，并写出同名
`.characterization.json`。`imu-collector validate` 会根据 `recording_kind` 自动决定诊断文件不要求 MKV。
分析代码升级后，可以在不改动原始 H5 的情况下重新生成报告：

```bash
uv run imu-collector analyze-characterization /path/to/characterization.h5
```

两个相反姿态分别记录在独立 H5 时，生成不修改原件的成对比较报告：

```bash
uv run imu-collector compare-accel-pair \
  /path/to/button-up.h5 \
  /path/to/button-down.h5 \
  --positive-stage long_static_button_up \
  --negative-stage button_face_down \
  --axis z
```

## 报告如何阅读

- `packet_metrics`：通知数量、400-byte 等包长直方图、接收间隔、长间隙、解析错误和回调丢弃。
- `timing_metrics`：用所有包末接收时刻拟合的候选样本率、重建后的样本间隔、每 60 包时间窗的局部频率与首尾漂移 ppm。
- `stage_metrics`：各阶段六列原始值的 mean、median、MAD、standard deviation、1%/99% 分位数与极值，以及每 60 秒窗口的中位数和窗口间跨度；长静态时可据此检查零偏漂移和离群噪声。
- `accel_calibration_candidates`：只有成对姿态都存在时，才从三个加速度候选原始列中找响应最大的列，并输出列映射候选、半跨度 `counts/g` 候选与中点 bias。
- `trailer_metrics`：4 个未知尾部字节的范围、唯一值数量和变化次数；不会擅自命名其语义。
- `unverified_items`：仍然禁止当作事实使用的结论。

2026-08-25 的 10 秒真实链路冒烟得到 10 个 400-byte 包、250 个候选样本、
25.00384 Hz、样本间隔中位数 39.993854 ms、0 长间隙、0 回调丢弃和 0 解析错误。
该实验姿态未控制，因此正确地产生了空的加速度校准候选；这条证据不能替代 30 分钟长测。

## 2026-08-25 按键面 ±Z 实测

按键面朝上和朝下分别稳定记录 10 分钟，两段均得到 600 个 400-byte 通知、
15,000 个候选样本、0 长间隙、0 回调丢弃和 0 解析错误。朝上/朝下三个加速度
候选列中位数分别为 `[188, -17, 4045]` 与 `[-13, 83, -4130]`。

成对差值为 `[201, -100, 8175]`。第三列响应为下一大列的约 40.67 倍，因此第三个
原始加速度列对应设备按键面法向/Z 轴是强候选；由中位数半跨度得到
`4087.5 counts/g`，中点得到零偏候选 `-42.5 counts`。这些值与 4096 接近，但不能据此
推断 MEMS 型号或直接把整个三轴校准标为 verified。报告继续固定
`training_eligible=false` 和 `calibration_verified=false`。

朝下姿态虽然物理摆放更稳，但统计噪声与朝上总体接近；其第三列在第一个一分钟窗口
从约 -4134 漂到 -4130，之后稳定。正式比例估计可增加“每个姿态先静置 60 秒再取样”的
操作规则，以减小翻转后的机械稳定或温漂影响。

接口面朝上（设备 −X 面）随后静态记录 5 分钟，得到 300 个 400-byte 通知、
7,500 个样本、0 长间隙、0 回调丢弃和 0 解析错误。第一加速度候选列中位数为
−4060 counts，且每分钟中位数无漂移，支持该原始列对应设备 X 轴的单侧候选。
第五候选列在该姿态出现明显宽噪声：1%–99% 分位约为 −69 到 +72，极值为
−240 到 +225；其他两个陀螺仪候选列仍较窄。该异常可能来自侧面摆放的方向性微动，
也可能是姿态相关数据行为，需在接口反面和重复摆放中判断；本段不能用于该列静态噪声基线。

接口反面朝上（设备 +X 面）也记录 5 分钟，得到 300 个 400-byte 通知、7,500 个样本、
0 长间隙、0 回调丢弃和 0 解析错误。第一加速度候选列中位数为 4119 counts。
接口面与反面成对差值为 `[8179, 222, -139]`，第一列响应为下一大列的约 36.84 倍；
因此第一原始加速度列对应设备 X 是强候选，`counts/g` 候选为 4089.5，零偏候选为
+29.5 counts。它与 Z 轴候选 4087.5 counts/g 只差 2 counts，支持当前加速度比例
约为 4096 counts/g 的假设，但 Y 轴和独立尺度依据仍缺失，不能标记 verified。

用户确认接口正反面的接触面均较小、会轻微不稳定。反面阶段第五候选列 1%–99% 分位
进一步扩展到约 -367 到 +357，极值约 -1191 到 +1147，而每分钟中位数仍接近 0；
这与方向性机械微摇一致。两段接口面数据可以用于稳健加速度中位数和轴映射候选，
但不能用于该候选陀螺仪列的静态本底噪声。反面记录另有一次约 1.360 秒通知到达延迟，
300 个应用通知仍全部存在，因此不把主机到达时间窗口的短时偏低解释成设备缺采样。

手扶吊坠/挂绳端朝上探索段在约 70 秒时按用户要求中断。平台从 partial 的副本重建时间并
生成最终诊断 H5，同时保留原 partial；由于原进程已退出，回调丢弃数明确标为 unknown，
不伪造为 0。该段三个加速度候选列中位数为 `[93, -4043, -35]`。

随后一分钟最初被误写为“接口面朝上”，用户随即更正：实际仍是吊坠/挂绳端朝上并全程手扶。
平台以原子副本方式把阶段更正为 `pendant_end_up_exploratory`、可靠性改为 exploratory，
同时在 H5 中保存旧标签、旧可靠性、旧备注、原文件 SHA-256、用户原因和更正时间。更正不改动
任何原始 payload、计数或时间数组。

两次手扶吊坠端加速度中位数分别为 `[93, -4043, -35]` 与 `[104, -4043, -31]`，高度一致；
第二原始加速度列的绝对响应远大于另外两列，因此它对应吊坠方向/设备 Y 轴是较强的探索性候选。
按当前“+Y 指向吊坠端”的坐标约定，吊坠端朝上时原始第二列为负，说明该原始列的符号候选与
目标 +Y 相反。由于两段均为手扶，横向分量和陀螺仪波动明显，只用于轴与大致符号判断，
不能生成正式 Y `counts/g`、零偏或静态噪声结论。

吊坠方向反面朝上也以手扶方式记录一分钟，得到 60 个 400-byte 通知、1,500 个样本、
0 长间隙、0 回调丢弃和 0 解析错误；第二加速度候选列中位数为 +4141。与更正后的
吊坠端朝上段成对差值为 `[210, -8184, -2]`，第二列响应为下一大列的约 38.97 倍。
因此第二原始加速度列对应设备 Y、且相对目标 +Y 坐标需翻转符号，是强探索性候选；
半跨度给出 4092.0 counts/g，中点给出 +49.0 counts 零偏候选。

当前 X/Y/Z 比例候选分别为 4089.5、4092.0、4087.5 counts/g，三者高度一致并接近
4096；原始加速度列到目标坐标的候选映射为 `[raw_ax, -raw_ay, raw_az]`。但 Y 的两侧
均为手扶数据，横向分量和陀螺仪明显包含人体抖动，所以 Y 报告状态为
`strong_exploratory_candidate`，整个三轴加速度校准仍保持 unverified，训练 SI 数组不解锁。
