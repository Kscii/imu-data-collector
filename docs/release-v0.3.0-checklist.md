# v0.3.0 Linux 源码与云端发布检查清单

2026-09-13：按本次确认的发布范围更新，取代原先要求本轮同时发布三种桌面安装包的计划。
本轮发布 `v0.3.0` 源码、Linux 安装说明和云端服务，不创建 `desktop-v0.3.0` 标签。

## 发布边界

- Windows/macOS 新版本暂缓，原因是客户文档中的系数与当前新设备不匹配；等待正确文档或匹配设备。
- Linux 新设备也保持 commissioning/test-only，正式 SI 未验证，`values_si` 为 NaN。
- 软件发布不批准或撤销设备 Snapshot，不设置团队 Current，不修改历史录制或发布新训练数据。
- 现有 HDF5 1.9／manifest 3.2 保存配置和 SI 来源；训练与客户交付仍使用 HDF5 3.2。
- 旧桌面包和历史验收证据保留；源码发布不能冒充新的跨平台实机验收。

## 候选代码检查

- 完整 Python/HDF5/API/协议/配置治理测试、Ruff 和差异检查通过。
- 前端行为与语言测试及 capture/annotation 两套构建通过，CI 包含前端测试步骤。
- 前后端 build ID 一致，缺少设备配置字段的旧 API 返回可操作提示。
- 中英文数据链路文档的相对链接及 Mermaid 图检查通过。
- Linux 安装说明使用锁定依赖和终端启动，不要求作者私有 GCS YAML 或固定仓库目录。
- 隔离目录验证应用启动、配置读取、语言显示、未验证设备的 prod 拦截与退出。
- 实机检查记录实际设备、原始包、时钟及文件结果；不可用的设备和未完成校准如实列为限制。

## 云端及发布顺序

1. 审查仅限本轮的改动，提交 collector 发布准备 PR，等待该提交 CI 完整通过。
2. 合并触发已有原子部署；核对部署 SHA、标注及上传代理健康、前后端版本和配置接口鉴权。
3. 部署前记录上一 release、服务和配置完整性摘要；部署失败沿用现有回滚入口。
4. 验证既有配置 Current 和数据发布指针未被本轮改变；不以发布为由运行配置批准或迁移。
5. 云端验收通过后在同一提交创建 `v0.3.0`，以[发布说明](releases/v0.3.0.md)和源码下载交付。
6. 将实际 CI、部署、Linux 检查结果与未验证项保存为 Release 验证附件；不把计划项记为通过。

本文件定义验收要求，最终状态以 Release 附件和同一提交的 CI/部署证据为准。
