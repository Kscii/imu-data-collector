# 客户六轴传感器采集协议基线

## 文档来源与效力

- 来源：`/home/kscii/Downloads/6-Axis Sensor Data Collection Project.pdf`
- 当前约定：把该 PDF 作为客户需求基线；其中没有说明或存在歧义的技术细节，必须在本项目
  文档中显式标为“项目补充”或“待客户确认”，不能伪装成客户原文。
- 当前平台只在文档中维护 SOP，不在 WebUI 中实现 A01–F05 计划选择、步骤计时、安全确认框
  或自动停止。

## 采集目的与动作原则

目标是建立供老年人跌倒检测算法训练和学术验证使用的胸前六轴 IMU 数据集。实验者模拟老年
动作时应保持缓慢、平稳，避免冲刺、大步跨越或跳跃式跌倒。所有跌倒只能在受控环境和防护
区域中进行。

## 佩戴、安全与人员要求

- IMU 位于胸前，使用弹性束带紧贴身体。
- 行走、转身和撞击后不得发生明显晃动、旋转或轴向移位。
- 跌倒区域完整铺设 15–20 cm 高密度防护垫或体操垫。
- 参与者全程佩戴轻量头盔、护膝和护肘。
- 客户文档要求现场至少 2–3 人协助录制和监护。
- 开始前确认无线连接与电量正常。

平台目前不会强制确认以上事项，也不会把它们写成 H5 内的合规证明。正式采集的线下负责人
必须自行保存知情同意、伦理审批和安全执行记录。

## 一次录制的建议顺序

客户原文只要求在开始时按下或轻拍传感器。由于按设备按钮可能改变蓝牙状态，项目暂将其解释
为“轻拍外壳”，不按功能键。为了比较时钟偏移与漂移，项目补充一个结束锚点：

1. 操作者点击开始录制，确认视频和 IMU 均已实际落盘。
2. 轻拍传感器外壳，镜头必须清楚看到手与外壳首次接触。
3. 等待轻拍振动消失。
4. 参与者立正静止至少 3 秒，作为该条录制的重力方向基线。
5. 执行预定 ADL 或 ADL + Fall 动作。
6. 如果包含跌倒，落地后保持躺卧且完全静止至少 5 秒。
7. 在安全、稳定的情况下执行结束轻拍。
8. 操作者点击停止，等待 H5 与 MKV 完成收尾。

静止 3 秒必须发生在开始落盘之后，否则不能成为数据中的基线。轻拍及其振动会原样保留在
raw H5/MKV 中，作为可审计的同步证据，但在标注中使用 `sync_tap` 显式排除，冻结训练数据时
不得作为 ADL 或跌倒样本。平台可自动提出“开始至开始轻拍后 1 秒”和“结束轻拍前 0.5 秒至
录制末尾”的排除草稿，仍由标注者核对边界。

## 客户动作代码

### 跌倒

| 代码 | 中文含义 |
|---|---|
| F01 | 行走中绊倒或向前倾倒 |
| F02 | 滑倒或失衡后向后跌倒 |
| F03 | 向右侧跌倒 |
| F04 | 向左侧跌倒 |
| F05 | 暈厥、膝软或垂直下沉式跌倒 |

### 日常生活活动

| 代码 | 中文含义 |
|---|---|
| A01 | 正常平地来回走动及相似生活场景 |
| A02 | 站立并执行上肢任务 |
| A03 | 缓慢坐下与站起 |
| A04 | 缓慢躺下、起身和离床或沙发 |
| A05 | 上下楼梯；客户文档同时列出搭乘电梯 |
| A06 | 不下蹲的弯腰取物 |
| A07 | 蹲下及相似任务 |

客户允许单一 ADL 连续 3–5 分钟，也允许多个 ADL 连续组合。ADL + Fall 模式要求跌倒位于
序列末尾。

## 当前交付边界与待确认项

- 原始产物仍为同一次开始到停止对应的一对 H5 + MKV；一次录制可以包含多个动作。
- 客户 PDF 给出 `.csv` 文件名示例，但没有明确字段、单位或是否为硬性交付格式。本阶段不生成
  CSV，交付前必须向客户确认。
- 客户 PDF 没有规定 30 Hz。平台保存实测约 25 Hz IMU 与约 30 FPS 视频的真实时间戳；严格
  30 Hz 只在同步、校准和标注完成后的派生阶段生成。
- 客户动作代码目前只保留在本 SOP，不写入 WebUI 或 H5 结构化计划元数据。这意味着平台不能
  自动检查“计划动作”和“实际标注”是否一致。
- 客户没有定义跌倒 onset、impact 或逐窗口标签规则；这些内容由独立标注语义文档管理。
