# 联合试采 `xfan0282_test_01`

## 目的与数据边界

本次只验证 CW12EU-T、摄像头、时间戳、同步、回放和标注能否形成完整闭环。
它不是正式跌倒采集，不包含模拟跌倒。请求参数固定为：

```text
participant_id = xfan0282
collection_id  = xfan0282_test_01
data_tier      = test
```

H5 与本地 catalog 必须保留 `data_tier=test`，`training_eligible` 必须始终为 false。
原始 H5/MKV 只保存在 `~/IMUData`，不上传，不进入 Git 或 Git LFS。

## 录制前检查

1. 手机上的 nRF Connect 已断开 CW12EU-T。
2. IMU 固定在胸前，按键面朝身体外侧，挂绳端朝向头部；录制中途不重新佩戴。
3. 第二次录制使用外接罗技 C930c 的彩色采集节点 `/dev/video4`，选择
   1920×1080、30 fps，画面不包含无关隐私内容。
4. 平台不录音，磁盘剩余空间不低于配置门限。
5. WebUI 明确显示 `test · 永久禁止训练`。

## 验收项目

- 最终目录包含同名 `.h5` 与 `.mkv`，正常完成时不只留下 `.partial.*`。
- IMU 平均频率为 24.5–25.5 Hz，回调丢弃和解析错误均为 0，样本时间严格递增。
- 视频为 H.264 1920×1080，离线中位 FPS 为 29–31，逐帧 PTS 严格递增。
- WebUI 可连续显示预览、实际 FPS、六轴原始计数、BLE 状态、包数、样本数和磁盘空间。
- 浏览器可回放录制视频；若 MKV 不兼容，只生成由 MKV SHA-256 标识的可重建 MP4 缓存，不覆盖原件。
- 三个同步锚点覆盖录制大部分时间，`scale` 在 0.995–1.005，RMS 不超过 40 ms，`quality=verified`。
- 至少保存并重新读取一个 `walking` 和一个 `sit_down` 非跌倒区间，标注修订号递增。

## 实际结果

### 第一次录制：保留为失败验收样本

- recording ID：`20260825T140029.696839Z_xfan0282`

- 文件大小：H5 约 660 KiB，MKV 约 225 MiB。
- 数据边界：H5 为 schema `1.1.0`，`data_tier=test`、`training_eligible=false`。
- IMU：309 个通知、7725 个候选样本、25.00014 Hz、最大通知间隔约
  1080.08 ms、0 解析错误。两次实时健康检查均为 0 回调丢弃，但本版本尚未把最终值
  持久化到普通采集 H5，因此最终报告只能标为 unknown；后续代码已补齐持久化。
- 视频：H.264 1920×1080，共 9303 帧，PTS 跨度约 309.134 秒；其中 260 个相邻帧
  PTS 重复、没有时间倒退。原始总帧跨度约 30.09 FPS，去除同刻重复帧后的有效唯一
  时间点约 29.25 FPS。该问题违反严格递增门禁，因此本轮不能进入同步验收。
- 收尾：最终 `.h5` 与 `.mkv` 均存在，没有只留下 `.partial.*`；结构校验唯一错误为
  `video PTS are not strictly increasing`。同步和标注尚未执行。
- 佩戴事件：用户确认按键面始终朝身体外侧；初期吊坠/挂绳端朝上，后期因固定松动，
  最终变成接口面朝下。变化时刻未知，因此不能假定整段 X/Y 轴相对人体方向一致。

处置：保留原始 H5/MKV 和 SHA-256，不原地修复。定位到编码输出的 B 帧重排序与
摄像头实际输入帧率共同影响 PTS；录制器改为禁用 B 帧并使用 VFR，只保存具有唯一源
时间戳的真实帧，不使用重复画面伪装 30 FPS。短测发现摄像头在近乎全黑画面下会降至
约 10 FPS，因此第二次正式试采前还必须确认镜头无遮挡且光线充足。

状态：第一次录制未通过，等待光线检查后重新执行完整五分钟闭环。任何失败都保留
原始证据，不降低阈值或把失败文件改名伪装为成功。

### 常驻预览与落盘切换回归

统一设备预览已由真实 CW12EU-T 与罗技 C930c 验收：非录制时 IMU 约 25 Hz、视频

2026-08-26 一次后端重启后出现 Firefox 预览空白，但后端帧计数约 10 FPS 持续增长。只读
诊断确认 FFmpeg、640×360 JPEG、multipart 边界和浏览器 TCP 长连接均正常；根因范围收敛到
浏览器对未声明分段长度的 MJPEG 流兼容性。平台现为每个 JPEG 分段显式写入
`Content-Length`，并增加 `no-store/no-cache` 与禁止代理缓冲响应头。修复后 38 个 Python
测试通过，用户在真实 Firefox 页面确认画面恢复。该修复只影响内存预览传输，不修改原始
H5/MKV 或录制编码路径。
