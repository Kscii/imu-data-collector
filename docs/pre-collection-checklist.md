# 每场次正式采集检查清单

这份清单用于当前 Arch + CW12EU-T + 罗技 C930c 组合。它负责防止“软件可以录，但本场数据
不可信”；不能替代参与者知情同意、跌倒保护人员和场地安全方案。

## 开始设备预览前

- 确认参与者 UniKey、动作计划、知情同意和现场安全人员；高风险跌倒不得单人执行。
- IMU 已充分充电并从充电线断开。当前协议没有可靠电量字段，不能把 WebUI 无电量显示解释
  为电量充足。
- 手机 nRF Connect 已断开且不会自动重连；同一时刻只允许本机后端持有 BLE 会话。
- IMU 固定在左胸，按键面朝身体外侧、吊坠端朝头部；夹具不松动、不压迫按键和接口。
- C930c 已接入，镜头无遮挡，画面不包含无关隐私区域，固定照明不会在动作期间切换。
- 本机只运行 systemd 管理的一个后端，不再额外执行前台 `imu-collector start`。

## 设备预览检查

打开 `http://127.0.0.1:8765`，点击“连接预览设备”，至少观察 5 秒：

- BLE 显示已连接，最后一包持续刷新，IMU 估算频率接近 25 Hz；
- 六轴曲线随轻微移动响应，静止时没有持续饱和、跳零或长时间冻结；
- 摄像头输入实时 FPS 接近 30，浏览器预览约 10 属于正常设计值；
- 固定曝光状态没有警告，画面亮度足以看清人体、胸前 IMU 与接触动作；
- 磁盘剩余空间高于 20 GiB，并足以覆盖预计录制时长；
- 参与者身份、批次 ID、`test/prod` 和 C930c 稳定 camera ID 均正确。

任何一项失败都先停止预览并排查，不通过刷新页面掩盖设备状态。`prod` 开始按钮还会再次检查
固定控件回读和最近源输入 FPS；门禁失败时不得改录成 `test` 后冒充正式数据。

## 每条录制

1. 确认选择 `prod`，开始录制后等待画面和姿态稳定。
2. 在开头做一次镜头可见的外壳轻拍；视频语义是“手首次接触”，IMU 语义是“首个明显响应”。
3. 执行动作；设备松动、重新佩戴、遮挡、他人入镜或安全中止必须记下时间和原因。
4. 结束前再做一次同样轻拍，随后停止录制；摘下设备必须发生在停止之后。
5. 不把轻拍、摘戴、调整和质量异常标成日常活动；标注时使用明确排除区间。

## 停止后的快速验收

- 录制状态为 `ready`，不是 `.partial`、`failed` 或 `needs_attention`；
- H5 与 MKV 同时存在，录制时长合理；
- IMU 约 25 Hz，无解析错误、回调丢弃或无法解释的长间隙；
- 视频整段 PTS 帧率不低于 27 FPS，无重复或倒退 PTS；
- 新 H5 的 calibration profile 为 `cw12eu_t_83fc90141ea4_v1_20260827`，且固定曝光回读已保存；
- 回看开头、动作、结尾三个位置，确认构图、方向和动作语义；
- 本地原件验证完成前不删除；发布后确认 manifest、大小和 SHA-256 全部成功。

若只是软件演示、校准复测或流程试验，应从开始就选 `test`，并用清楚的批次名记录目的；
`test` 永远不能升级成训练数据。
