# 生产动捕标注工作台

2026-10-09 功能分支实现，尚未部署。真实录制、外部设备和管理员自动区间标注实验保持各自的数据域。生产默认使用新的动捕区间工作台；管理员实验入口仍保留。

## 使用与数据规则

审核队列按规范动捕 SHA-256 聚合，详情可选择该动捕的 IMU 版本。曲线、播放进度及区间高亮共用时钟；编辑时暂停。用户可修改类别/边界、自由填写区间语义及有时间锚点的备注，检查后通过整条录制。生产页面没有逐段确认状态，保存后保持当前位置，手动进入下一条。

未知区间继续监督屏蔽；全未知录制可审核但不进入训练快照。相邻同类合并，独立跌倒不合并；没有完整 onset/impact/stop 的跌倒不导出标签。主活动24类、IMU20类投影与HDF5 **3.3.0**均保留，辅助标签暂不参与。

同一原始动捕、同一已审核时间范围内的新 IMU，在机器 QA 和完整发布后自动继承语义与质量，保留原人工审核证据。改变姿势、轨迹、实际速度则是新动捕。可以单独拒绝某个 IMU 版本，也可因源动捕质量问题拒绝全部版本。历史质量结果继续可见，旧标签只作提示，实验修正只导入生产草稿。

模型更新保留人工修改和已通过版本，只呈现新旧差异；载入建议成为草稿，再次通过才影响新快照。并发编辑使用180秒租约和revision CAS；本地未保存草稿可恢复/下载。浏览器的恢复副本不能覆盖更晚的服务器审核。

首份快照允许增量创建，按明确 IMU 配置冻结已通过且含已知区间的录制。同 motion、时间范围和配置只选最新版本；不同配置分别出快照。旧快照保持不变，下载沿用现有鉴权路径。

## 服务边界

- `/api/v1/synthetic/motions`：队列、详情、租约、草稿、录制审核、配置和快照。
- `/api/v1/synthetic/motions/models`：管理员模型列表/启用/失败任务重试；启用触发全量后台重标，已通过人工版本保留。
- `/api/v1/synthetic/temporal/*`：原实验功能，全部后台校验管理员身份。
- 旧生产 `/candidates/.../reviews` 和 `/labels` 写入返回410；历史读取保留。

Ubuntu SDK 独立生成 motion-only 特征和 IMU。特征上传后由云端 `imu-motion-label-worker` 使用单线程 ONNX Runtime CPU 推理；不需要 GPU。动捕、SMPL+H 资产和配方决定特征身份；模型哈希决定分数缓存，阈值变化可复用分数。单机 SQLite 保存目录/持久任务，对象存储保存不可变审核事实及CAS指针。API和worker共享同一catalog目录和发布锁；多主机并行未支持。

模型初次基线需显式导入；新候选报告必须绑定 ONNX、metadata 和当前基线，并满足20条盲标参考、准确率下降≤1个百分点、覆盖率提升≥10个百分点、边界误差不变差和匹配数不下降。未完成验收时继续使用现用模型。报告工具位于 simulator `tools/evaluate_motion_model.py`；工程上线不代表新模型准确率已获验证。

## 本地联调与部署

`scripts/serve-motion-preview.py --local-store STORE --state-dir STATE --actor engineering-ui` 只监听loopback，授予指定本地工程身份权限，不能用于公网服务。工程审核写在独立store，不写入用户已有实验。生产必须使用现有IAP配置。

`scripts/migrate-motion-review-drafts.py` 默认只预演迁移并刷新可重建本地索引；`--apply`才写草稿。先登记完整候选、特征、变体和独立验证保护组；源/目标store必须已存在。仅精确匹配候选/时间的人工修正可迁移，已有生产编辑优先，人工通过数始终为0。

发布包必须包含新 `configs/systemd/imu-motion-labels.service`、`motion-labels`依赖组与更新后的deploy/rollback脚本。单元使用现有kscii服务身份，限1个CPU/768MiB，写目录为`/var/lib/imu-annotation`。切换版本前停止worker，新版本健康后启动；回滚到无worker的旧版本时停止该单元，不删除状态与审核历史。旧安装脚本不会自动认识新worker，需要随发布更新。

本地后端412项、前端12组、CI Ruff与构建通过；工程浏览器四种尺寸覆盖1366×650至1920×1080，区间同步、备注、草稿与整条通过保持光标均通过。工程审核产生的真实HDF5 3.3由模拟器和benchmark共同校验通过。另从Ubuntu只读取得一条6.6秒真实开发样本，在Arch验证新特征/预测与旧结果逐值一致，CPU热推理中位2.46ms，分数缓存复用通过；不是全库准确率结论。

在Ubuntu执行新代码的联调尚未进行，向Ubuntu传输代码包被自动审批拒绝，需该目的主机与测试目录的明确授权。云端正式发布也尚未执行；不能把本地工程接受当作真实人工通过。
