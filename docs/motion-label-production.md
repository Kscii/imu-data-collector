## 使用与数据规则

审核队列按规范动捕 SHA-256 聚合，详情可选择该动捕的 IMU 版本。曲线、播放进度及区间高亮共用时钟；编辑时暂停。用户可修改类别/边界、自由填写区间语义及有时间锚点的备注，检查后通过整条录制。生产页面没有逐段确认状态，保存后保持当前位置，手动进入下一条。

未知区间继续监督屏蔽；全未知录制可审核但不进入训练快照。相邻普通同类合并，独立跌倒不合并；相邻姿态转换需人工处理。确认跌倒但撞击点未知时仍保留分类正例，整条暂缓正式 3.3 事件导出。当前代码使用 `motion-temporal 3.0.0` 的16类，历史24类和20类仍可读取；HDF5 **3.3.0**保持不变，辅助标签暂不参与。

新规则 `2026-10-09.4` 使用一个姿态转换类别和六种支撑姿态端点，保留真实中间姿态，不强制最短停留。页面只显示简短标签；长定义暂存在临时文档。整条审核必须提交页面加载的 `activity_rules_version`；旧页面提交返回409，服务端不改写旧记录。界面移除时间数字编辑及保存草稿按钮，切分/合并按钮和本机草稿恢复仍保留。快捷键为空格、S/M、P/N 和 Ctrl/⌘+Enter；提交前检查语义并定位错误。

同一原始动捕、同一已审核时间范围内的新 IMU，在机器 QA 和完整发布后自动继承语义与质量，保留原人工审核证据。改变姿势、轨迹、实际速度则是新动捕。可以单独拒绝某个 IMU 版本，也可因源动捕质量问题拒绝全部版本。历史质量结果继续可见，旧标签只作提示，实验修正只导入生产草稿。

模型更新保留人工修改和已通过版本，只呈现新旧差异；载入建议成为草稿，再次通过才影响新快照。并发编辑使用180秒租约和revision CAS；本地未保存草稿可恢复/下载。浏览器的恢复副本不能覆盖更晚的服务器审核。

首份快照允许增量创建，按明确 IMU 配置冻结已通过且含已知区间的录制。同 motion、时间范围和配置只选最新版本；不同配置分别出快照。旧快照保持不变，下载沿用现有鉴权路径。

## 服务边界

- `/api/v1/synthetic/motions`：队列、详情、租约、草稿、录制审核、配置和快照。
- `/api/v1/synthetic/motions/models`：管理员模型列表/启用/失败任务重试；模型启用与批处理分开，已通过人工版本保留。
- `/api/v1/synthetic/temporal/*`：原实验功能，全部后台校验管理员身份。
- 旧生产 `/candidates/.../reviews` 和 `/labels` 写入返回410；历史读取保留。

Ubuntu SDK 独立生成 motion-only 特征和 IMU。特征上传后由云端 `imu-motion-label-worker` 使用单线程 ONNX Runtime CPU 推理；不需要 GPU。动捕、SMPL+H 资产和配方决定特征身份；特征／ONNX／分数 runtime 决定网络缓存；时序分数、可靠性掩码按 metadata 与 runtime 哈希另存，阈值变化可复用网络分数。单机 SQLite 保存目录/持久任务，对象存储保存不可变审核事实及CAS指针。API和worker共享同一catalog目录和发布锁；多主机并行未支持。

模型初次基线需显式导入。新候选须提供绑定确切 ONNX、metadata、runtime 和基线的 v2 独立验证报告：普通高可信精度≥95%，相对 A 的覆盖率增加≥10个百分点、边界不退步、词表外误标不增加。跌倒另需20个完整事件／5组／40个难负例，事件精度召回≥90%，起止P90≤0.5秒、撞击P90≤0.2秒。既有基线可回滚，但不能绕过首次全量门槛。

`POST /api/v1/synthetic/motions/batch` 仅管理员可用，提交 `control` 与 `expected_control_sha256`，以CAS保存计划。`batch-control.json` 缺失或 `mode=paused` 时worker不领取任务。`sample` 限100条显式motion白名单，`full` 还要求最终release的100条云端实测及30%余量的总耗时预测。首次100条与后续处理共用不超过7200秒的 `started_unix/deadline_unix`；Ubuntu生产端也传相同 `--deadline-unix`。到期进程停止，账本可恢复，但不自动续给新预算。`incremental` 持续处理也须完整质量门槛通过。

完整候选与高可信区间分开保存／评估。局部与前后文证据必须同时过校准阈值；未校准模型不能宣称高可信。词表外和缺失时间不强行补类别。普通人工“整条通过”会确认所有当前显示的已知类别，包括低可信建议；缺失撞击点和未知范围仍屏蔽。教师分数、时序分数与可靠性掩码保留供下一轮IMU蒸馏使用，本轮没有训练六轴学生模型。

## 候选预览与规模化登记（2026-10-09）

候选预览与正式启用分离。管理员可从“模型与快照”进入只读比较，或使用
`?view=synthetic&motion_preview=iteration-20261009-c&lang=zh-CN`；同一播放器切换冻结人工结果、基线和候选 C，不领取编辑租约、不恢复或写入本地草稿、不更新正式预测指针。返回正式审核后才通过既有 revision/CAS 流程修改。预览冻结模型/metadata 哈希、规则版本和人工 revision，服务端仍检查独立验证组保护。

只读接口为 `GET /api/v1/synthetic/motions/previews`、`GET .../previews/{id}` 和
`GET .../previews/{id}/{motion_sha256}`，均要求管理员。`scripts/import-motion-preview.py` 默认只验证输入；显式 `--apply` 将比较写入不可变预览命名空间，不注册或启用候选模型。

特征与 IMU 变体发布完成后追加 `imu.motion_label_feed.v1` 收据，引用两个不可变 manifest 的路径和哈希。后台持久化增量游标；首次和每日对账分别分页遍历 feature manifests 与 variants，失败单独记录、有界重试，不阻止后续有效收据。特征或候选提交绑定不一致不能进入审核队列。模型入队按 release 和 motion 行游标增量推进，换 release 从头安排，已有人工审核不被覆盖。

管理员模型接口同时报告任务耗时和登记错误数。任务耗时含下载、预测及结果保存，不含 Ubuntu 首次特征准备，也不能单独当作全库端到端估计。首轮先用 22 来源的 100 条实测，按来源外推加 30% 余量；预计总处理超过两小时则暂停剩余批次。两小时是处理预算，不包含开发、人工检查和部署。
